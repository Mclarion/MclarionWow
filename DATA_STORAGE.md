## Data paths and ownership

- WoW owns and writes the account-wide `MclarionWowData` SavedVariables table at `/reload`, logout or exit; an addon assignment is memory-only until then. No arbitrary TXT/CSV file or upload is written by Lua. The player's remote website requires deliberate selection of the game-written `MclarionWow.lua`; the Windows client has a separate manual import. Website imports do not populate the client's own database.
- The code files `MclarionWow.lua` and `MclarionWow.toc` under `Interface/AddOns/MclarionWow/` are **not** the SavedVariables file. The TOC remains `Interface: 16001`, `AllowLoadGameType: camelot`, `SavedVariables: MclarionWowData`; version 0.11.0 changes no storage schema or wire format.
- Native WoW combat logs stay separate. Opting into combat logging starts WoW's `LoggingCombat` on world entry; turning off auto-start does not stop a running logger. The separately clicked **Stop logging now** control may also stop a logger started by someone else.
- Never open, edit, publish or print a player SavedVariables payload while WoW runs. Keep private names, item IDs, GUIDs, game-account paths and log contents out of this repository and handoff.

## Current schema and capture

| Key | Stored data | Population |
| --- | --- | --- |
| `schema` | `1` or `2` | Existing schema 1 is upgraded to 2 on a successful opted-in metadata capture; unknown schemas are refused. |
| `settings` | Five first-run-off booleans | `autoCombatLog`, `autoCharacterCapture`, `autoBagCapture`, `autoBankCapture`, `autoItemMetadataCapture`; settings window via minimap icon or `/mhwowui`. |
| `characters[guid]` | Up to 20 `MHWOW2`/fallback `MHWOW1` history strings | Opted-in own-character captures on login, equipment/zone/post-combat changes and five-minute retries. |
| `bags[guid]` | Up to 20 `MHWOWB1` own-bag numeric totals | Opted-in bag open/update, login, post-combat and periodic retries. |
| `bank[guid]` | Up to 20 `MHWOWK1` own-character-bank numeric totals | Opted-in view of purchased **character-bank** tabs only; bank open/slot/tab changes and player-selected pages. |
| `items[guid]` | Latest bag/equipment `MHWOWI1` plus ordered own-bank `MHWOWI1` pages | Separately opted-in, complete cached out-of-combat item scans; schema 2. Up to 9 bank pages of 128 IDs each. |

All capture paths reject combat, secret/protected APIs and malformed/over-limit state. They never navigate bank pages, inspect account/Warband bank tabs, or guess missing item metadata. Consecutive unchanged history states deduplicate ignoring timestamp and the oldest is dropped above 20. Complete metadata pages replace prior records only after validation; partial/missing cache results preserve existing items. Account-wide item metadata is bounded to 1 MiB. An icon value in `MHWOWI1` is a numeric *texture file ID*, not image bytes. A client with item IDs but no metadata for that character/build cannot create a missing icon by refreshing existing images.

## One-file item-detail contract (schema 2)

**Goal:** after opt-in, WoW's existing account SavedVariables file also holds item names/details now available only through `MHWOWI1` clipboard exports. No extra game file, external scanner, or automatic website upload. The existing `characters`, `bags`, and `bank` histories retain their meanings; bank and bag item totals are already stored in schema 1. Native combat logs remain separate.

**Schema 2:** preserve all schema-1 keys and add `items[guid] = { bags = <latest MHWOWI1>, bank = { [1] = <MHWOWI1>, ... [9] = <MHWOWI1> } }`. These describe **numeric Lua array entries**: WoW may serialize sequential bank pages as implicit entries (`{ "MHWOWI1...", ... }`) instead of `[1] = ...`; data-only readers must accept both without changing page order. `bags` metadata covers only observed own-bag/equipped item IDs; each `bank` page covers only observed IDs from the visible own character-bank view. The section names preserve provenance, and every existing `MHWOWI1` payload includes its GUID, timestamp, build and locale. Metadata never creates inventory quantities; `MHWOWB1`/`MHWOWK1` remain authoritative for totals. Missing cache names stay unresolved rather than guessed. One bag/equipment payload plus at most nine bank pages per GUID, each at most 32,768 bytes; impose a conservative account-wide item-metadata byte budget below the website's 4 MB file limit and refuse a new capture rather than truncate or overwrite valid older data.

Add a **separate default-off item-details consent switch**. After explicit opt-in, attempt bounded, out-of-combat metadata capture on own bag/equipment changes and safe periodic retries, and on the player's own bank-open/page/slot events. Do not navigate bank tabs, read account/Warband-bank data, execute protected APIs, or erase earlier valid metadata when cache entries are missing. Validate the complete replacement before mutating SavedVariables; unchanged item state does not churn timestamps. WoW writes the file only on its normal `/reload`/logout/exit cycle.
