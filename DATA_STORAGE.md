WoW writes in-memory addon SavedVariables to disk only at `/reload`, logout or normal exit. The addon does not create arbitrary TXT/CSV or upload files; a dashboard capture or last-success timestamp means **in memory**, not persisted on disk. ## Capture controls and triggers

Fresh-profile legacy five choices and progression six automatic choices are off; previous player choices may differ. `/vaultkeeper` and `/mhwowui` open the same dashboard. Legacy Character/Bags/Bank/Items **Scan** requires its corresponding preference (Bank can attempt item details if only that separate preference is on); progression Quests/Reputation/Gold/Currencies/Honor/Titles **Scan** works without enabling automatic capture. All scans guard world entry, combat, secret/protected APIs and malformed/over-limit state. No scan or opt-in is triggered by dashboard open/navigation/refresh/history paging.

- Legacy character: world entry, equipment/level/zone notifications, post-combat, 300-second fallback. Bags: world entry, own-bag open/delayed update, post-combat, fallback. Item details: world/equipment/bag/post-combat/fallback for bags/gear; own-bank events for bank details. Bank totals/details: visible **own-character-bank** open/slot/tab/page changes only (no closed-bank timer, no account/Warband bank or tab navigation). Automatic empty-after-populated bags/bank refuses until explicit visual confirmation via Scan; incomplete item cache preserves older complete metadata.
- Progression: world entry, post-combat, 300-second fallback and guarded bounded retry; `QUEST_LOG_UPDATE` for active quests, `UPDATE_FACTION` for visible faction rows, optional `PLAYER_MONEY` for gold, `CURRENCY_DISPLAY_UPDATE` for visible currencies, `PLAYER_PVP_RANK_CHANGED` for supported honor/rank. No title-specific event. Money/currency/rank bursts debounce from first event for 0.35 seconds; unavailable and same-second work stays queued for guarded retry, bounded exponential backoff up to 300 seconds. Event payloads are not stored. Optional event-registration failure retains world/post-combat/timer paths. Manual actions never grant auto consent.
- Optional metadata: successful validated visible faction/currency **numeric** scans (manual or opted-in automatic, including unchanged numeric results) may enrich observed IDs without blocking those histories. Separate `/vkmspells on` is explicit spell consent (absent/false by default); `/vkmspells off` clears pending IDs. Only validated `UNIT_SPELLCAST_SUCCEEDED` for `unitTarget="player"` queues numeric spell IDs; a 64-ID deduplicated queue enriches at most four per out-of-combat wakeup, with up to three missing-text attempts and asynchronous spell-text/load-event or timer wakeups. No spellbook enumeration, arbitrary-ID lookup, cast-event ledger, gameplay action or combat-log parser. See `METADATA_CONTRACT.md` for exact data/source limits.
- Native combat logging: `autoCombatLog` can start WoW's own logger at world entry; unchecking auto-start does not stop an already running log. **Stop logging now** is a separate explicit control that can stop a logger started outside the addon. Only the preference, not event data, belongs to `MclarionWowData`.

## Stored shapes and reader limits

Legacy schema 1 can advance to 2 only on a successful opted-in item metadata save, preserving old character/bag/bank histories. History writers deduplicate meaningful unchanged state (ignoring timestamp), retain at most 20 per owner and fail closed on combat, secret/protected or unsafe values. Legacy `items[guid] = {bags=<MHWOWI1>,bank={<ordered MHWOWI1 pages>}}` is **latest per source**, not 20 snapshots; both implicit Lua array entries and explicit numeric keys denote ordered bank pages. Account-wide item metadata cap: **1 MiB**; icon is numeric texture file ID, not image bytes. Metadata rows do not create bag/bank quantities.

Each progression root remains schema 1 and independent of the legacy root: the quest active-log list has at most 128 UI rows/100 IDs, reputation visible list 256 UI rows/200 character-provenance faction IDs, currency visible list 256 UI rows/200 classified balances per record, title known mask list up to 512 IDs. Gold is copper balance, honor is supported counters/rank (not total earned honor), titles lack acquisition dates. Unavailable, hidden, collapsed or unknown scope is **not zero or absence**. Every progression writer charges a provisional **3,000,000-byte structural projection** across the legacy and four progression roots; candidate metadata also has a **524,288-byte metadata charge** and a six-root projection. These are in-memory structural budgets, **not** a worst-case WoW serializer bound or 4 MB upload guarantee. Failure preserves prior roots.

Candidate `VaultkeeperMetadataData = {schema=1, spellCaptureEnabled=false, records={...}}` has at most **400** build/locale variants. Reputation/currency keys encode type:ID:build:locale; spell keys append **observer GUID** to prevent cross-character contextual text reuse. Records include type, numeric ID/build, locale, observed server time, observer GUID, scope and name; optional description/icon/quality mean **unknown** when absent. Reputation/currency labels come from successful visible numeric observations; spell name/original-icon (icon fallback) and optional `descriptionProvenance="player-spellcast:C_Spell.GetSpellDescription"` are contextual to the observing player/client. Read-only labels require current observer/build/locale and escape game markup. Metadata contains no balances, faction standings, spell effects/cooldowns/damage or cast times; numeric dynamic values remain in their existing owner histories. **Items** retain the older schema-2 source-specific pipeline, not a new metadata row. **Maps, titles, talents, professions/recipes** are pending metadata work; **quests are excluded** from this new catalog. Full contract and source links: `METADATA_CONTRACT.md`.

### Read-only dashboard field inventory

`MclarionWow_DashboardDetails(key, requested)` reads already-loaded SavedVariables belonging to the current character and validates the **entire selected history** before display. Defaults to newest; **Older/Newer** choose one of at most 20 retained observations by index (oldest = 1, newest = count). The selected record and adjacent comparison are not a cumulative timeline or guarantee of intervening events. Item metadata is latest-per-source, Spell rows are observed descriptive records, and Combat has no addon event-record count. Account currency is independently latest-only for the current observer; a foreign latest account observation hides those values even if an older own record exists. Session-only last request/changed-capture timestamps are distinct from saved observation time/build and from disk modification. Missing/protected/sparse/foreign/malformed/over-limit data shows unavailable/no observation rather than zero; decoded text escapes WoW pipe/control markup. Output caps at **32,768 bytes** with a whole-line truncation notice, not pagination or a complete export. The 0.12.6 UI has twelve sections and ten Scan buttons; Combat and Spells have no Scan.
